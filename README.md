# iPrent Helpdesk

مشروع إدارة تذاكر وصيانة الطابعات والعملاء — واجهة ويب مبنية بـ Flask.

## الملخّص

- خادم Flask يقدم واجهة لعمل تذاكر، مراقبة طابعات، وتنبيهات ذكية.
- قاعدة بيانات SQLite محليّة: `database.db` (مستثناة في `.gitignore`).

## التشغيل محلياً (Windows)

1. افتح PowerShell في مجلد المشروع.
2. أنشئ/فعّل بيئة افتراضية (إذا لم تكن موجودة):

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

3. ثبّت التبعيات:

```powershell
pip install -r requirements.txt
```

4. شغّل التطبيق:

```powershell
python app.py
```

افتح المتصفح على `http://127.0.0.1:5000/`.

## ملاحظة حول الملفات الكبيرة

- ملف النموذج `models/ticket_ai_model.h5` مستثنى في `.gitignore` — لا تضفه إلى الريبو.

## ملفات مهمة
- `app.py` — تطبيق Flask
- `config.py` — إعدادات محلية (قاعدة بيانات محلية، SECRET_KEY)
- `requirements.txt` — تبعيات بايثون
- `migrate_db.py` — تحديث سكيمة SQLite عند الحاجة

## نظرة عامة على المشروع

**iPrent Helpdisk** هو نظام ويب متكامل لإدارة تذاكر الدعم الفني مصمم خصيصاً لإدارة مشاكل تقنية المعلومات بشكل احترافي. النظام يدعم:

- **إدارة شاملة للتذاكر**: إنشاء ومتابعة وحل التذاكر بسهولة
- **مراقبة الأجهزة**: مراقبة حالة الطابعات والخوادم وأجهزة الشبكة
- **تصنيف ذكي**: استخدام الذكاء الاصطناعي لتصنيف التذاكر تلقائياً
- **تنبيهات تلقائية**: تنبيهات فورية للمشاكل المهمة
- **تحليلات متقدمة**: إحصائيات وتحليلات شاملة عن الأداء
- **واجهة عربية كاملة**: دعم كامل للغة العربية مع خطوط عربية مخصصة

## خطوات التنصيب

### 1. تثبيت المكتبات المطلوبة

افتح PowerShell أو Command Prompt في مجلد المشروع وقم بتشغيل:

```bash
pip install -r requirements.txt
```

هذا الأمر سيثبت جميع المكتبات المطلوبة تلقائياً. قد تستغرق العملية بضع دقائق.

**ملاحظة**: إذا واجهت مشاكل في تثبيت TensorFlow، يمكنك تثبيته بشكل منفصل:
```bash
pip install tensorflow==2.13.0
```

### 2. إعداد قاعدة البيانات

قاعدة البيانات SQLite ستنشأ تلقائياً عند أول تشغيل للتطبيق. لا حاجة لأي إعداد يدوي.

عند أول تشغيل، سيتم:
- إنشاء ملف `database.db`
- إنشاء جميع الجداول المطلوبة
- إضافة مستخدم افتراضي (admin/admin123)
- إضافة طابعات افتراضية للاختبار
- إضافة أجهزة افتراضية (خوادم، محطات عمل، أجهزة شبكة)
- إضافة تذاكر تجريبية

### 3. تدريب نموذج الذكاء الاصطناعي (اختياري)

إذا كنت تريد استخدام ميزة التصنيف التلقائي والذكاء الاصطناعي، قم بتشغيل:

```bash
python train_model.py
```

**ملاحظات مهمة**:
- يمكنك تشغيل التطبيق بدون تدريب النموذج، لكن ميزة التصنيف التلقائي لن تعمل
- التدريب يحتاج إلى تذاكر في قاعدة البيانات (يتم إضافتها تلقائياً عند أول تشغيل)
- عملية التدريب قد تستغرق عدة دقائق حسب عدد التذاكر
- بعد التدريب، سيتم حفظ النموذج في مجلد `models/`

## قاعدة البيانات

التطبيق يستخدم **SQLite** كقاعدة بيانات. الملف `database.db` يُنشأ تلقائياً ويحتوي على الجداول التالية:

### الجداول الرئيسية

1. **printers** - معلومات الطابعات
   - id, name, ip_address, model, status, ink_level, last_seen

2. **tickets** - التذاكر
   - id, printer_id, ticket_type, device_name, affected_users_count, reporter_email, title, description, priority, status, created_at, updated_at

3. **ticket_comments** - تعليقات التذاكر
   - id, ticket_id, author, message, created_at

4. **users** - المستخدمون
   - id, username, password_hash

5. **alerts** - التنبيهات
   - id, printer_id, ticket_id, alert_type, message, severity, is_read, created_at

6. **maintenance_schedules** - جداول الصيانة
   - id, printer_id, maintenance_type, scheduled_date, completed_date, status, notes, created_at

7. **ink_predictions** - توقعات نفاد الحبر
   - id, printer_id, current_level, predicted_depletion_date, confidence_score, created_at

8. **ticket_categories** - تصنيفات التذاكر (من الذكاء الاصطناعي)
   - id, ticket_id, category, confidence, created_at

9. **ai_responses** - استجابات الذكاء الاصطناعي
   - id, ticket_id, initial_response, troubleshooting_steps, common_solutions, guidance, confidence_score, created_at

10. **devices** - الأجهزة
    - id, name, device_type, ip_address, location, status, last_seen, created_at

### العلاقات بين الجداول

- **Ticket** → **Printer** (علاقة اختيارية)
- **Ticket** → **Device** (عن طريق device_name)
- **TicketComment** → **Ticket** (علاقة إلزامية)
- **Alert** → **Printer** و **Ticket** (علاقات اختيارية)
- **MaintenanceSchedule** → **Printer** (علاقة إلزامية)
- **InkPrediction** → **Printer** (علاقة إلزامية)
- **TicketCategory** → **Ticket** (علاقة إلزامية)
- **AIResponse** → **Ticket** (علاقة إلزامية)

## نظام الذكاء الاصطناعي

### الوظائف الرئيسية

1. **تصنيف التذاكر تلقائياً**
   - تحليل عنوان ووصف التذكرة
   - تصنيفها إلى: hardware, software, network, ink, paper, printer, other
   - إعطاء درجة ثقة للتصنيف

2. **تحديد الأولوية تلقائياً**
   - تحليل محتوى التذكرة
   - تحديد الأولوية: Low, Medium, High, Critical
   - اعتماداً على الكلمات المفتاحية والسياق

3. **اقتراح حلول أولية**
   - اقتراح خطوات استكشاف الأخطاء
   - اقتراح حلول شائعة
   - توجيهات قبل تدخل فريق الدعم

### كيفية عمل النموذج

1. **معالجة النص**: تنظيف وتحويل النص إلى شكل قابل للمعالجة
2. **Tokenization**: تحويل النص إلى أرقام (tokens)
3. **Embedding**: تحويل الأرقام إلى متجهات ذات معنى
4. **LSTM**: معالجة التسلسل لفهم السياق
5. **Classification**: تصنيف النص إلى فئات وأولويات

### تدريب النموذج

```bash
python train_model.py
```

العملية تشمل:
- جلب التذاكر من قاعدة البيانات
- تحضير البيانات للتدريب
- بناء النموذج
- تدريب النموذج (عادة 50 epoch)
- حفظ النموذج المدرب في `models/`

## 📚 شرح المصطلحات الخاصة بالمشروع

هذا القسم يشرح المصطلحات الخاصة بنظام iPrent Helpdisk فقط.

### مصطلحات التذاكر

#### **Ticket (تذكرة)**
طلب دعم فني أو مشكلة تقنية يتم تسجيلها في النظام. كل تذكرة تحتوي على عنوان، وصف، أولوية، حالة، ونوع المشكلة. النموذج `Ticket` موجود في `app.py`.

#### **Ticket Type (نوع التذكرة)**
تصنيف التذكرة حسب نوع المشكلة. الأنواع المتاحة: `printer` (طابعة)، `network` (شبكة)، `hardware` (أجهزة)، `software` (برمجيات)، `other` (أخرى).

#### **Priority (الأولوية)**
مستوى أهمية التذكرة. القيم المتاحة: `Low` (منخفضة)، `Medium` (متوسطة)، `High` (عالية)، `Critical` (حرجة). تحدد أولوية المعالجة.

#### **Status (الحالة)**
حالة التذكرة الحالية. القيم المتاحة: `Open` (مفتوحة)، `In Progress` (قيد المعالجة)، `Resolved` (محلولة)، `Closed` (مغلقة).

#### **Ticket Category (تصنيف التذكرة)**
تصنيف تلقائي للتذكرة باستخدام الذكاء الاصطناعي. النموذج `TicketCategory` في `app.py` يخزن الفئة ودرجة الثقة.

#### **Ticket Comment (تعليق التذكرة)**
ملاحظة أو رد يُضاف على التذكرة. النموذج `TicketComment` في `app.py` يخزن التعليقات مع المؤلف والتاريخ.

#### **AI Response (استجابة الذكاء الاصطناعي)**
استجابة تلقائية من الذكاء الاصطناعي للتذكرة. النموذج `AIResponse` في `app.py` يخزن الحلول المقترحة وخطوات استكشاف الأخطاء.

### مصطلحات الطابعات

#### **Printer (طابعة)**
جهاز طباعة يتم مراقبته في النظام. النموذج `Printer` في `app.py` يحتوي على الاسم، عنوان IP، الموديل، الحالة، ومستوى الحبر.

#### **Ink Level (مستوى الحبر)**
نسبة الحبر المتبقي في الطابعة (من 0 إلى 100). يتم تحديثه تلقائياً عبر SNMP أو يدوياً.

#### **Ink Prediction (توقع نفاد الحبر)**
توقع تاريخ نفاد الحبر بناءً على الاستخدام الحالي. النموذج `InkPrediction` في `app.py` يخزن التوقعات مع درجة الثقة.

### مصطلحات الأجهزة

#### **Device (جهاز)**
أي جهاز تقني يتم مراقبته. النموذج `Device` في `app.py` يدعم أنواع: `printer` (طابعة)، `server` (خادم)، `workstation` (محطة عمل)، `network_device` (جهاز شبكة).

#### **Device Status (حالة الجهاز)**
حالة الجهاز الحالية. القيم: `online` (متصل)، `offline` (غير متصل)، `warning` (تحذير)، `error` (خطأ)، `unknown` (غير معروف).

### مصطلحات التنبيهات

#### **Alert (تنبيه)**
إشعار عن مشكلة مهمة. النموذج `Alert` في `app.py` يحتوي على نوع التنبيه، الرسالة، والخطورة.

#### **Alert Type (نوع التنبيه)**
نوع التنبيه. الأنواع: `low_ink` (انخفاض الحبر)، `offline` (انقطاع)، `high_priority` (أولوية عالية)، `maintenance_due` (صيانة مستحقة).

#### **Severity (الخطورة)**
مستوى خطورة التنبيه. القيم: `low` (منخفضة)، `medium` (متوسطة)، `high` (عالية)، `critical` (حرجة).

### مصطلحات الصيانة

#### **Maintenance Schedule (جدول الصيانة)**
موعد مبرمج لصيانة الطابعة. النموذج `MaintenanceSchedule` في `app.py` يخزن نوع الصيانة، التاريخ، والحالة.

#### **Maintenance Type (نوع الصيانة)**
نوع الصيانة المبرمجة. الأنواع: `cleaning` (تنظيف)، `inspection` (فحص)، `repair` (إصلاح)، `replacement` (استبدال).

### مصطلحات لوحة التحكم

#### **Dashboard (لوحة التحكم)**
الصفحة الرئيسية التي تعرض إحصائيات شاملة عن النظام. ملف `dashboard.html` في مجلد `templates/` يحتوي على لوحة التحكم.

#### **Affected Users Count (عدد المستخدمين المتأثرين)**
عدد المستخدمين المتأثرين بالمشكلة. يُستخدم لتحديد أولوية التذكرة.

#### **Reporter Email (بريد المرسل)**
البريد الإلكتروني لشخص الذي أبلغ عن المشكلة. يُستخدم للتواصل والتحديثات.

## الخلاصة

**iPrent Helpdisk** هو نظام متكامل وقوي لإدارة تذاكر الدعم الفني. مع ميزات الذكاء الاصطناعي، لوحة التحكم الشاملة، وإدارة الأجهزة، يوفر النظام حلاً كاملاً لإدارة المشاكل التقنية.

ابدأ بتشغيل التطبيق، جرّب الميزات، وعدّل الأكواد حسب احتياجاتك. النظام مرن وقابل للتخصيص بالكامل.
